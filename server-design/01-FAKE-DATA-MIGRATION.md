# 가짜 데이터 전수 목록 · 실서버 전환 방법

> 지금 무엇이 가짜이고, 각각을 어떻게 진짜로 바꾸는가.
> **대부분은 "지우는" 게 아니라 "시드를 서버에서 받는" 것으로 끝납니다.**

---

## 0. 이 프로젝트는 이 전환을 예상하고 짜여 있다

코드 주석이 직접 말합니다:

| 파일 | 주석 |
|---|---|
| `core/guilds.ts` | *"실제 멀티플레이가 붙으면 **이 모듈만 서버 조회로 갈아끼우면 된다**"* |
| `core/chat.ts` | *"`ChatTransport` 인터페이스만 세워 두고 지금은 mock 을 꽂는다. 나중에 WebSocket 구현으로 교체하면 **UI 는 그대로 간다**"* |
| `core/ranking.ts` | *"실제 서버가 없으므로 '서버 인구'를 결정론적으로 생성한다"* |
| `state/live.ts` | *"게임 스토어와 분리해 둔다 — 1~10초마다 갱신되는 소셜 데이터가 게임 화면 전체를 리렌더시키면 안 되기 때문"* |

**이음새가 이미 있습니다.** 새로 뚫을 필요가 없습니다.

## 1. 전환 분류 — 3가지 유형뿐입니다

| 유형 | 뜻 | 서버 부담 |
|---|---|---|
| **S) 시드만 받는다** | 결정론 생성을 그대로 두고 시드를 서버가 준다 | 거의 0 |
| **R) 실데이터로 교체** | 진짜 다른 플레이어 데이터가 필요하다 | 중 |

## 2. 전수 목록

### X) 지워야 하는 것

| 대상 | 위치 | 조치 |
|---|---|---|
| **쿠폰 코드** | `core/coupons.ts` — `iloverakdos`(10만 골드), `iloverakdos2`(주문서 100장×전종류) | **삭제.** 또는 서버 발급 코드 체계로 전환 (`COUPON_RESET_SEQ` 가 이미 있어 리셋 가능) |
| **mock 채팅** | `core/chat.ts` — `createMockTransport`, `SMALL_TALK` 18줄 | prod 빌드에서 배제. 동적 `import()` 로 분리해 트리셰이킹 |
| **가짜 피드** | `core/feed.ts` — `fakeEvent`, `randomNick` | Phase 3 까지는 유지, 실채팅 붙은 뒤 제거 |

> `randomNick` 은 랭킹·길드·피드·투기장 고스트가 **전부 공유**합니다.
> 실데이터로 바꿀 때 한 번에 다 바뀌므로 순서를 맞춰야 합니다.

### S) 시드만 서버에서 받는 것 — 여기가 대부분입니다

| 대상 | 현재 시드 | 서버가 줄 것 | 갱신 주기 |
|---|---|---|---|
| **주식 시세** | 초당, 로컬 시계 | 일별 시드 + 서버 시간 | 하루 1회 |
| **주식 뉴스 이벤트** | `upcomingNews` 시간 슬롯 | 같은 시드 | 하루 1회 |
| **크리처 러쉬 대진·배당** | 5분 슬롯 시드 | 같은 시드 | 하루 1회 |
| **선술집 소문** | `RUMOR_PERIOD_MS` 8시간 슬롯 | 같은 시드 | 하루 1회 |
| **복권 추첨** | (회차 + 발급번호) 시드 | 회차별 시드 | 회차마다 |
| **퀘스트 보드** | `questBoard` 슬롯 시드 | 슬롯 시드 | 하루 1회 |

**핵심: 이건 서버 계산이 아닙니다.** `GET /seeds?day=20260823` 이 하루 한 번 작은 JSON 을
내려주고, 클라이언트가 기존 `seeded()` 로 똑같이 생성합니다.

```
GET /seeds/20260823
{ "stock": "a3f...", "rush": "9c1...", "rumor": "77e...", "quest": "b04...", "lottery": { "1043": "e21..." } }
```

- **모든 플레이어가 같은 시세·같은 대진·같은 소문을 봅니다** — 그게 "같은 세계에 있다"는 감각의 정체입니다.
- 대역폭: 하루 1회 수백 바이트. **CDN 캐시가 100% 먹습니다.**
- 서버 CPU 0. DB 쓰기 0.
- ⚠ 클라이언트가 시드를 위조하면 자기 화면만 달라집니다. 배팅 결과가 서버에 안 남으니
  무해합니다 (§치트 정책 — 방치 대상).

### R) 실데이터로 교체해야 하는 것

| 대상 | 현재 | 전환 |
|---|---|---|
| **랭킹** | `ranking.ts` `POPULATION = 99` 결정론 생성 | 실제 집계. **하루 1회 배치** — `ranking.ts` 가 이미 "하루 단위로 고정" 설계라 리듬이 맞다 |
| **길드 목록** | `guilds.ts` `NAMES` 12개 하드코딩, `guildsFor(weekKey)` | DB 조회. 내 길드(`MY_GUILD_ID='mine'`)는 이미 실데이터라 **NPC 길드만 걷어내면 됨** |
| **길드 구성원** | `membersOf()` 결정론 | DB 조회 |
| **채팅** | mock transport | WebSocket 구현체 |
| **투기장 상대** | 고스트 (`myCur × (0.85~1.2)`) | 실제 플레이어 스냅샷 풀에서 매칭 |
| **쿠지·가챠 공유 재고** | *"다른 사람의 소비를 시간 기반으로 결정론 시뮬"* (`draw.ts`) | **원자적 카운터.** 유한 재고라 진짜 공유돼야 의미가 있다 |

## 3. 전환 순서가 중요한 것 2개

### 3-1. 랭킹 — 절대 분포를 지켜야 한다

`ranking.ts` 주석에 이렇게 있습니다:

> *"가짜 플레이어의 능력치를 내 능력치에 맞춰 만들면 내 순위가 영원히 중간에 머문다.
> 그래서 **절대 분포**로 만든다 — 성장하면 실제로 순위가 올라간다."*

**실서버 초기에는 인구가 적어서 이 문제가 반대로 터집니다.** 100명이 있으면 신규 유저가
바로 50등입니다. 그러면 랭킹이 성장 지표로 기능하지 않습니다.

→ **초기에는 실데이터 + NPC 를 섞습니다.** 실제 플레이어를 절대 분포에 꽂고, 빈 구간을
기존 결정론 NPC 로 채웁니다. 인구가 늘면 NPC 비율을 줄입니다.
`POPULATION` 을 서버가 내려주는 값으로 바꾸면 이게 자연스럽게 됩니다.

### 3-2. 쿠지 재고 — 유한 재고가 이 시스템의 전부다

`draw.ts` 는 500칸 박스에서 **비복원 추출**을 하고, 그래서 환급률이 설계 시점에 확정됩니다.
지금은 남의 소비를 시간 기반으로 흉내내고 있습니다.

실서버에서는 **원자적 감소**가 필수입니다:

```
POST /draw/kuji   → { grade, prize, remaining }
```

- Redis `DECR` 또는 DB row lock. **낙관적 갱신 금지** — 같은 칸을 두 명이 뽑으면 환급률이 깨집니다.
- 사이클 리셋(`cycleKey`)도 서버가 소유합니다.
- 클라이언트의 `draws` 필드(`{ dayKey, today, cycleKey, inCycle }`)는 **표시용 캐시**로 격하되고,
  진실은 서버에 있습니다.

> ⚠ 이건 §치트 정책의 예외입니다. 쿠지는 **공유 재고**라 위조하면 남의 확률을 바꿉니다.
> 뽑기만은 서버 권위여야 합니다.

## 4. 시간 의존 필드 전수 (Phase 1 에서 `now()` 로 치환할 곳)

`DEVELOPMENT.md` 가 목록을 이미 갖고 있습니다 — *"전부 로컬 시계 기준 경과 시간 계산"*:

| 대상 | 주기 | 저장 필드 |
|---|---|---|
| 체력 | 10분/1 | `stamina`, `staminaAt` |
| 투기장 뱃지 | 10분/1 | `arena` |
| 대출 만기 | 24~72시간 | `loans[].dueAt`, `delinquentUntil` |
| 크리처 러쉬 | 5분 | `rushSlot`, `rushWeek`, `rushEpoch` |
| 주식 | 초당 | `stockTickAt`, `stockDay` |
| 시즌 | 2주 | `arena` |
| 퀘스트 리셋 | 1시간 | `questBoard.slot` |
| 복권 추첨 | 매일 20시 | `lottery` |
| 출석체크 | 일별 | `attendance.lastDay` |
| 선술집 | 일별 | `tavern.dayKey` |
| 쿠지·가챠 | 일별 + 사이클 | `draws` |
| 일일 첫 클리어 | 일별 | `dailyBonus` |

**전부 `Date.now()` 를 `now()` 로 바꾸면 한 번에 해결됩니다.**
`onRehydrateStorage` 가 복귀 시 `tick()` 을 부르는 구조도 그대로 갑니다 —
`tick()` 안의 시계만 서버 보정된 값이 되면 됩니다.
