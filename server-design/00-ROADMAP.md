# 서버 전환 로드맵 · 출시 전략

> `docs/` 는 다른 세션이 쓰고 있어서 이 폴더에 따로 정리합니다.
> 문서 3개: **00 로드맵(이 파일)** · 01 가짜 데이터 전환 · 02 백엔드 설계

---

## 1. 먼저 — 서버는 게임을 시뮬레이션하지 않는다

이 게임은 **99% 싱글플레이어에 가짜 소셜 껍데기**가 붙은 구조입니다.
랭킹·길드·채팅·피드가 전부 결정론적으로 생성되고 있습니다 (`ranking.ts`, `guilds.ts`, `feed.ts`).

그래서 서버가 관장해야 하는 건 **딱 4개**입니다:

| # | 관장 | 없으면 생기는 일 |
|---|---|---|
| 1 | **시간** | 기기 시계를 돌려서 체력·쿨타임·만기·시즌을 전부 뚫는다 |
| 2 | **저장** | 재설치하면 계정이 사라진다. 결제하면 환불 폭풍 |
| 3 | **결제** | 영수증 검증 없이는 IAP 를 팔 수 없다 |
| 4 | **공유 상태** | 랭킹·길드·채팅·쿠지 재고가 진짜가 아니다 |

**게임 로직(강화 판정·전투·도박)은 서버로 옮기지 않습니다.**
옮기는 순간 프로젝트가 10배가 되고, 이 게임에서 얻는 게 거의 없습니다 (§5 치트 항목 참조).

## 2. 원칙 — 결정론은 서버로 옮기지 마세요

주식(초당 등락), 크리처 러쉬 대진, 선술집 소문, 이벤트 피드는 이미
**"시간 슬롯을 시드로 한 결정론적 생성"** 입니다. `DEVELOPMENT.md` 가 그렇게 설계했다고
명시하고 있습니다.

> 서버가 **시드만** 내려주면 모든 클라이언트가 같은 결과를 냅니다.
> 대역폭 0, 서버 CPU 0, DB 쓰기 0.

이걸 "제대로" 만들려고 서버 계산으로 바꾸면 **초당 트래픽**이 생기고 비용이 폭발합니다.
주식이 초당 갱신이니 DAU 1,000 이면 초당 1,000 요청입니다. 절대 하지 마세요.

**이 프로젝트의 가장 큰 자산은 `src/state/migrate.ts` 입니다.** 주석에 이렇게 적혀 있습니다:

> *"저장본을 신뢰하지 않는다 — 기본값에서 시작해 **검증된 값만** 덮는다.
> core 만 import 한다 (RN 없이 테스트 가능해야 한다)."*

**그게 정확히 서버가 필요한 것입니다.** 신뢰할 수 없는 클라이언트 페이로드 검증기가
이미 있고, RN 의존이 없어서 Node 에서 그대로 돌아갑니다. 서버 검증 레이어를 새로 쓸 필요가 없습니다.

## 3. 단계

### Phase 0 — 서버 없이 지금 해야 하는 것 (반나절)

| 할 일 | 왜 |
|---|---|
| **쿠폰 코드 제거** | `core/coupons.ts` 의 `iloverakdos` = **10만 골드**, `iloverakdos2` = 전 종류 주문서 100장. 하나 퍼지면 경제가 즉사하고 IAP 도 같이 죽는다 |
| mock 채팅을 prod 빌드에서 차단 | `createMockTransport` 가 프로덕션에 들어가면 가짜 대화가 진짜처럼 보인다 |
| DEV 전용 코드 트리셰이킹 확인 | 기존 교훈이 있다 — dev 전용 모듈은 동적 `import()` 로 분리 |
| 앱 아이콘·스플래시 확인 | `app.json` 은 이미 흑백으로 설정돼 있다 |

### Phase 1 — 시간 서버 (하루)

**엔드포인트 하나.** `GET /time` → `{ now: 1756... }`

부팅 시 `offset = serverNow − Date.now()` 를 구해 두고, 게임의 모든 시간 계산이
`now()` 헬퍼를 통과하게 바꿉니다.

```ts
// src/core/clock.ts (신규)
let offset = 0;
export const setOffset = (o: number) => { offset = o; };
export const now = () => Date.now() + offset;
```

그리고 `Date.now()` 를 전수 치환합니다. **이 한 개 엔드포인트가 체력·투기장 뱃지·대출
만기·시즌·러쉬·복권 추첨·퀘스트 리셋·출석체크를 전부 방어합니다.**

- 비용: Cloudflare Worker 무료 티어로 충분 (요청당 바이트 수십)
- ⚠ 오프라인 대응: 실패하면 `offset = 0` 으로 진행하되 **저장본에 `offlineSince` 를 남기고**,
  다음 접속에서 서버 시간과 크게 어긋나면 그 구간의 시간 보상(체력 회복 등)을 잘라냅니다.

### Phase 2 — 계정 + 클라우드 세이브 (1~2주)

`store.ts` 에 이미 자리가 있습니다:

```ts
account: { provider: 'google' | 'guest'; id: string; email?: string } | null;
signedUp: boolean;
diamonds: number;             // 유료 화폐 자리
cashItems: Record<string, number>;
```

- Google Sign-In → `account` 채움
- 저장본 전체를 JSON 문서로 업로드/다운로드 (§02 문서 참조)
- **`migrate.ts` 를 서버에서 재사용**해 업로드 페이로드를 검증
- 충돌은 `rev` 단조 증가로 해결 (서버 `rev` 가 더 크면 거부하고 서버본을 내려줌)

### Phase 3 — 공유 상태 (2~3주)

| 대상 | 방식 | 갱신 주기 |
|---|---|---|
| 랭킹 | 배치 집계 → 캐시 | 하루 1회 (`ranking.ts` 가 이미 "하루 단위 고정" 설계) |
| 길드 목록·구성원 | DB | 주 1회 스냅샷 (`guildsFor(weekKey)` 와 같은 리듬) |
| 채팅 | WebSocket | 실시간 |
| 쿠지·가챠 공유 재고 | 원자적 카운터 | 실시간 |

### Phase 4 — 결제 (1주)

플레이스토어 결제 + 영수증 서버 검증. **광고 제거 상품 하나부터.**
`cashItems` 자리가 이미 있으니 상품 지급 경로만 붙입니다.

## 4. ⚠ 치트는 막을 수 없습니다 — 무엇을 포기할지 정하세요

클라이언트가 모든 판정을 하므로 **저장본 위조·메모리 조작은 근본적으로 막을 수 없습니다.**
완전히 막으려면 강화·전투·도박 판정을 서버로 옮겨야 하는데, 그건 다른 게임입니다.

실용적인 선을 그으면:

| 대상 | 보호 수준 |
|---|---|
| **랭킹 · 길드 기여도 · 투기장 점수** | **보호한다.** 상한 검사 + 증가율 검사. 이상하면 **랭킹에서만 제외**(계정은 유지) |
| 결제로 얻은 재화 (`diamonds`, `cashItems`) | **보호한다.** 서버가 소유권을 갖고, 클라이언트 저장본 값은 무시 |
| 그 외 전부 (골드·장비·강화) | **방치한다.** 싱글 게임에서 자기 저장본 조작은 자기 손해다 |

> 랭킹만 지키면 됩니다. 남의 즐거움을 해치는 건 랭킹뿐이니까요.

## 5. 출시 전략 — 웹 먼저가 맞습니다. 단, 이유가 다릅니다

**"플레이스토어가 안 될까봐"가 아닙니다.** 세 가지 실무적 이유입니다:

1. **Expo 는 웹과 앱을 동시에 냅니다.** `react-native-web` 이 이미 dependencies 에 있습니다.
   하나를 고르는 게 아니라 **웹이 먼저 나가고 앱이 따라가는** 겁니다.
2. **서버를 붙이는 건 위험한 작업이고, 웹은 즉시 롤백됩니다.** 앱은 심사가 있어서
   치명적 버그를 하루 이상 방치하게 됩니다. Phase 1~2 의 시행착오를 웹에서 겪는 게 맞습니다.
3. **베타 테스터를 모으는 데 설치 마찰이 0** 입니다. 링크 하나면 됩니다.

### 플레이스토어는 생각보다 막혀 있지 않습니다

- **청소년이용불가여도 결제는 정상 작동합니다.** 청불이 깎는 건 노출·피처링·광고 eCPM 이고,
  IAP 에는 영향이 없습니다.
- **예상 등급은 무료로 10분에 확인됩니다.** Play Console 에 앱 등록 후 IARC 설문을 채우면
  제출·심사 전에 예상 등급이 나옵니다. 앱을 완성할 필요도 공개할 필요도 없습니다.
  **추측하지 말고 이걸 먼저 하세요.**
- **내부 테스트 트랙(Internal testing)은 심사가 거의 없습니다.** 최대 100명까지 즉시 배포됩니다.
  베타를 여기서 해도 됩니다.

### ⚠ 개인 개발자 계정의 실제 장벽

개인(개인 사업자 아님) 계정으로 **프로덕션 출시** 하려면 그 전에 **비공개 테스트를
일정 인원 × 일정 기간** 채우라는 요구사항이 있습니다 (제가 아는 범위로는 12명 × 14일).
정책이 자주 바뀌니 **Play Console 의 현재 문구를 직접 확인**하셔야 합니다.

이게 실제로는 가장 큰 장벽이고, **웹 베타를 먼저 하는 게 이 요구사항에도 유리합니다** —
웹에서 모은 사람들이 그대로 비공개 테스터가 되어 줍니다.

### 권하는 순서

```
Phase 0 정리
   ↓
웹 배포 (서버 없음, 로컬 저장) ── 커뮤니티에 던져서 재미가 있는지 본다
   ↓                              ← 여기서 재미가 없으면 서버를 만들 이유가 없다
Phase 1 시간 서버 (웹에 먼저 적용)
   ↓
Phase 2 계정 + 세이브 (웹에서 검증)
   ↓
Play Console IARC 설문 → 예상 등급 확인
   ↓
내부 테스트 트랙 (100명) → 비공개 테스트 (요구사항 충족)
   ↓
Phase 3 공유 상태 · Phase 4 결제
   ↓
프로덕션
```

**서버를 만들기 전에 웹으로 재미를 검증하는 게 가장 중요합니다.**
서버는 재미를 만들어 주지 않습니다. 재미가 있는 게임을 여러 명이 즐기게 해 줄 뿐입니다.

## 6. 비용 감각

| 단계 | 스택 | DAU 1,000 기준 월 비용 |
|---|---|---|
| Phase 1 시간 | Cloudflare Workers | **$0** (무료 티어) |
| Phase 2 저장 | R2/S3 + Postgres(Neon·Supabase 무료) | **$0 ~ $5** |
| Phase 3 랭킹 배치 | Cron Trigger + 캐시 | **$0** |
| Phase 3 채팅 | Durable Objects 또는 소형 WS 인스턴스 | **$5 ~ $10** |

**DAU 1,000 까지 월 $0~$15 로 갑니다.** 저장본이 후반에도 37KB 라
DAU 1,000 전체가 36MB 밖에 안 됩니다 (§02 참조). 부담될 규모가 아닙니다.
