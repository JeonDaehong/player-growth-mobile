# 강화 마일스톤 설계 (v1)

> **+5강 단위로 추가 아이템레벨.** 지금 +1~+15 는 랜드마크 없는 평지라, 강화 15번을
> 해도 "조금씩 올랐다" 밖에 없습니다. 5칸마다 계단을 놓습니다.
>
> 관련: `src/core/tiers.ts`(`itemLevel` · `fullSetIlvl` · `maxSetIlvl`),
> `src/core/enhance.ts`(`artisanOdds`), `src/core/combat.ts`(`CURVE_SCALE`)
>
**적용 범위가 두 갈래입니다:**
> - **일반 장비(티어 1~10)** — 마일스톤 **무료**. 강화 진행의 랜드마크
> - **장인 무구** — 마일스톤이 **봉인**되어 있고, **해방**(유료)으로 하나씩 연다 (§6)

---

## 1. 공식

```ts
/** +5n 마일스톤 = 그 티어 강화 min(n, 3) 회분 */
export function milestoneBonus(kind: PartKind, tier: Tier, level: number): number {
  const step = TIERS[tier].inc * kindWeight(kind);   // 강화 1회 상승분
  let sum = 0;
  for (let m = 5; m <= level; m += 5) sum += step * Math.min(m / 5, 3);
  return sum;
}

// itemLevel() 에 더한다
base + inc * kindWeight(kind) * level + milestoneBonus(kind, tier, level)
```

| 강화 | 보너스 | 누적 |
|---|---|---|
| +5 | 강화 **1회분** | 1회분 |
| +10 | 강화 **2회분** | 3회분 |
| +15 | 강화 **3회분** | 6회분 |
| +20 이상 (장인) | 3회분 고정 | +5마다 3회분 |

장인 무구는 이 보너스가 **기본으로 적용되지 않습니다** — §6 의 해방으로 사야 합니다.

- 부위 가중치(`kindWeight`)를 그대로 곱하므로 무기가 더 크게 받습니다. 기존 규칙과 일관됩니다.
- **장인 무구는 +15 이후 3회분 고정**입니다. `min(n, 3)` 캡이 없으면 무한 강화 구간에서
  보너스가 2차식으로 폭발합니다 (+50 이면 55회분).

## 2. 실측 값

**무기(검) 아이템레벨 — 현재 → 마일스톤 적용**

| 티어 | +0 | +5 | +10 | +15 |
|---|---|---|---|---|
| 1 | 10 | 19 → **20** | 27 → **32** | 36 → **46** |
| 5 | 150 | 210 → **221** | 269 → **305** | 329 → **400** |
| 10 | 660 | 915 → **966** | 1,170 → **1,323** | 1,425 → **1,731** |

**풀셋(16슬롯 합)**

| 티어 | +10 | +15 |
|---|---|---|
| 1 | 339 → 398 (+17.4%) | 432 → **535** (+23.8%) |
| 5 | 3,653 → 4,028 (+10.3%) | 4,283 → **5,026** (+17.3%) |
| 10 | 15,930 → 17,541 (+10.1%) | 18,615 → **21,837** (+17.3%) |

저티어가 상대적으로 더 크게 오릅니다 (`base` 가 작아 보너스 비중이 큼). 초반 체감이 커지는
쪽이라 의도에 맞습니다 — DEVELOPMENT 의 "초반에 체감을 가장 크게 바꾸는 건 빈 칸 채우기"
철학과 같은 방향입니다.

## 3. 콘텐츠 곡선은 손댈 필요가 없다

`combat.ts` 가 이미 곡선을 `maxSetIlvl()` 에 묶어 놨습니다:

```ts
const CURVE_SCALE = maxSetIlvl() / LEGACY_MAX_SET;
export const exploreRecIlvl = (ch) => Math.round((10 + ch * 11) * SLOT_COUNT * CURVE_SCALE);
```

`maxSetIlvl()` 이 18,615 → **21,837** 로 오르면 `CURVE_SCALE` 이 1.048 → **1.230** 으로
자동 따라옵니다. 챕터 100 권장 = `maxSetIlvl()` 이 유지되므로 **용린 +15 풀셋의 챕터 100
승률 50% 가 그대로 보존됩니다.** 스모크 단언(`exploreRecIlvl(100) === maxSetIlvl()`)이
이걸 지킵니다.

보스의탑도 `towerTopIlvl()` = `fullSetIlvl(10, 12) + 정령석` 이라 같이 따라옵니다.

> 즉 **`itemLevel()` 한 곳만 고치면 나머지가 자동 정합**입니다.
> 이게 이 변경이 해방보다 훨씬 싼 이유입니다.

## 4. 마일스톤이 하락을 3~4배 아프게 만든다 (이게 핵심 효과)

티어 10 무기 기준:

| 하락 | 잃는 아이템레벨 | 평소(−1레벨) 대비 |
|---|---|---|
| +10 → +9 | **−153** | ×3 |
| +15 → +14 | **−204** | ×4 |

지금은 하락이 그냥 "−51" 입니다. 마일스톤을 넣으면 **+10 이나 +15 를 막 찍은 직후의
하락이 재앙**이 됩니다. 강화 확률표(+11 이후 하락 15~20%)를 그대로 두고도 긴장이 3~4배가
되는 셈이라, 이 게임의 정체성에 정확히 맞습니다.

부수 효과로 **파괴 방어·하락 보정 주문서의 가치가 자동으로 올라갑니다** (§4-3 의 20골드
하락 보정 주문서가 지금은 애매한데, 마일스톤 직후 구간에서 확실히 살아납니다).

## 5. 승급이 더 무거운 결정이 된다

티어 9 +15 무기에서 티어 10 으로 올릴 때, 원래 템렙을 회복하는 지점:

| | 현재 | 마일스톤 |
|---|---|---|
| T9 +15 | 1,132 | 1,377 |
| 회복 지점 | T10 **+10** | T10 **+12** |

승급 골짜기가 2칸 깊어집니다. **의도한 것으로 둡니다** — 승급은 100% 성공하고 비용만
큰 무통 행동이었는데, 이제 "지금 올릴까 +15 를 더 즐길까" 가 생깁니다.

⚠ 단, 승급 화면에 **"승급 후 템렙이 일시적으로 T10 +12 까지 낮아집니다"** 를 반드시
표시해야 합니다. 모르고 눌렀다가 약해지면 억울합니다 (내구도 표기와 같은 이유).

## 6. 해방 — 장인 무구의 마일스톤을 돈으로 연다

장인 무구는 **무한 강화**입니다. 즉 마일스톤이 +20, +25, +30 … 으로 **끝없이 생깁니다.**
그걸 기본으로 주면 공짜 무한 성장이 되고, 유료로 팔면 **끝나지 않는 골드 sink**가 됩니다.
후자를 택합니다.

> 둔카락스는 제 작품의 잠재력을 5칸마다 봉인해 두고 넘깁니다.
> `artisans.ts` flavor: *"한 번 넘긴 물건은 부러지기 전까지 다시 손대지 않는다."*
> 봉인을 푸는 값은 따로 받습니다.

### 6-1. 규칙

| 항목 | 규칙 |
|---|---|
| 단위 | **장비 1점**, **순서대로만** (+5 해방 없이 +10 해방 불가) |
| 비용 | **`10,000 × n` 골드** (n = 몇 번째 해방인가) |
| 효과 | 그 마일스톤의 보너스가 적용된다 (`min(n,3)` 회분) |
| 영속성 | **영구.** 하락으로 그 아래로 떨어져도 해방은 유지되고, 다시 올리면 부활한다 |
| 재료 | 없음 — **순수 골드 sink** |

**영구가 핵심입니다.** 하락 15% 로 해방이 무효화되면 30,000골드를 태우는 도박이 되어
아무도 안 삽니다. 하락의 아픔은 "보너스가 일시적으로 빠지고, 다시 올리는 강화비"가
담당합니다 — 지출은 영구, 손실은 일시적.

### 6-2. 비용과 효율 (장인 무기 기준, 강화 1회분 = 68 ilvl)

| 해방 | 강화 | 비용 | 보너스 | 골드/ilvl |
|---|---|---|---|---|
| 1번째 | +5 | 10,000골드 | +68 | 147 |
| 2번째 | +10 | 20,000골드 | +136 | 147 |
| 3번째 | +15 | 30,000골드 | +204 | 147 |
| 4번째 | +20 | 40,000골드 | +204 | 196 |
| 5번째 | +25 | 50,000골드 | +204 | 245 |
| 10번째 | +50 | 100,000골드 | +204 | 490 |
| 20번째 | +100 | 200,000골드 | +204 | 980 |

- 보너스는 3번째부터 **+204 고정**인데 비용은 계속 오릅니다 → **효율이 점점 나빠집니다.**
  무한 sink 의 필수 조건이고, "다음 해방은 항상 조금 더 아깝다"가 됩니다.
- **누적 5개(+25까지) = 150,000골드**, 같은 구간을 강화로 올리는 비용이 **160,000골드**입니다.
  한 줄로: **장인 무구를 올리는 데 드는 돈이 대략 두 배가 됩니다.**
- 강화 자체는 약 59골드/ilvl, 해방은 147골드/ilvl 부터 시작합니다.
  **해방은 항상 강화보다 비쌉니다** → 강화를 먼저 하고 여유가 생기면 해방합니다. 올바른 순서입니다.

### 6-3. ⚠ 전제조건 — 장인 확률표를 고쳐야 해방이 팔린다

`ARTISAN_ODDS = { success: 15, fail: 55, downgrade: 20, destroy: 10 }` 는 드리프트가
**−0.05** 입니다 (하락 20% > 성공 15%). 몬테카를로 실측:

| 확률 | +5 도달 | +10 도달 | 드리프트 | 파괴 |
|---|---|---|---|---|
| **현재** 15/55/20/10 | **1.9%** | **0.0%** | −0.05 | 10% |
| 하락↓ 15/70/10/5 | 13.0% | 1.4% | +0.05 | 5% |
| **제안** 25/60/15/0 | **100%** | **100%** | +0.10 | **0%** |

**지금 확률로는 +5 마일스톤에 도달할 확률이 1.9% 입니다.** 도달 못 하는 마일스톤의 봉인을
누가 10,000골드에 사겠습니까. 해방이라는 상품 자체가 성립하지 않습니다.

```ts
const ARTISAN_ODDS: Odds = { success: 25, fail: 60, downgrade: 15, destroy: 0 };
```

#### 6-3-1. 최종 — 한 줄짜리 등비 곡선, 하락도 파괴도 없음 (2026-08 개정 2차)

위 25% 를 **전 단계 고정**으로 넣었다가, 다시 "+1 50% → +16 25% 고정" 으로 완만하게
바꿨다가, 지금의 형태에 왔습니다. 두 번 다 같은 문제가 남았습니다.

- **고정 구간이 있으면 성장 감각이 +16 에서 끊깁니다.** +30 이나 +80 이나 같은 25% 라
  "위로 갈수록 어려워진다" 는 이 콘텐츠의 전제가 중간에 사라집니다.
- **하락 15% 가 무한 강화를 벌칙으로 만듭니다.** 마일스톤 때문에 하락 한 번에 3회분이
  빠지는데, 그건 "어렵게 올린 걸 되돌린다" 지 "천천히 올라간다" 가 아닙니다.
  사람은 되돌아가는 게임을 그만둡니다.

그래서 **점 두 개를 박고 그 사이를 등비로 잇는 한 줄**로 정리했습니다.

| 목표 단계 | +1 | +5 | +10 | +16 | +20 | +30 | +50 | +75 | +100 이상 |
|---|---|---|---|---|---|---|---|---|---|
| 성공률 | **60.0%** | 49.0% | 38.0% | 28.1% | 22.9% | 13.8% | 5.0% | 1.4% | **0.4%** |

```ts
ARTISAN_TOP = 60          // +1  (0 → 1 강)
ARTISAN_END = 0.4         // +100 (99 → 100 강). 그 아래로는 안 내려간다
ARTISAN_DECAY = (0.4 / 60) ** (1 / 99)   // ≈ ×0.9506, 한 칸당
```

- **하락 0 · 파괴 0.** 남는 확률은 전부 "실패(유지)" 입니다. 장인 무구는 올라가거나
  제자리일 뿐, 절대 내려가지도 부러지지도 않습니다.
- **브레이크는 곡선 자체입니다.** 하락으로 끌어내리지 않아도 +50 에서 5%, +75 에서 1.4%,
  +100 에서 0.4% 라 위로 갈수록 스스로 느려집니다. 페널티가 필요 없습니다.
- **0.4% 바닥을 두는 이유**는 무한 강화를 말 그대로 무한하게 두기 위해서입니다.
  계속 감쇠시키면 +150 쯤에서 사실상 0 이 되어 상한이 생깁니다.

**파괴를 0 으로 두는 근거는 그대로입니다:**

1. 파괴율이 0 이 아니면 기대 도달 레벨이 `드리프트 / 파괴율` 로 **유한**합니다.
   5% 만 남겨도 "무한 강화"가 거짓말이 됩니다.
2. 파괴되면 그 장비에 넣은 **해방 비용이 전부 날아갑니다.** 그럼 아무도 안 삽니다.

⚠ **해방(§6-2)의 투자/회수 표는 이 개정으로 움직입니다.** 예전 계산은 "+16 이상 25% 고정,
하락 15%" 를 전제로 한 것이라, 곡선이 계속 내려가는 지금은 높은 마일스톤일수록 도달이
느려집니다. 해방이 **더 귀해지는** 방향이라 sink 로서는 오히려 강해지지만,
숫자를 다시 쓸 때 §6-2 표부터 갱신해야 합니다.

`ARTISAN_DESTROY_REFUND`(30) 는 쓰이지 않게 되므로 제거합니다.

## 8. 남은 확인 사항

- **판매가와의 정합.** `economy.ts:sellPrice` 는 `sellBase + sellPerLevel × level` 이라
  아이템레벨을 안 씁니다. 즉 마일스톤은 판매가를 올리지 않습니다.
  회수율(24~29%)이 유지되는 건 좋지만, "템렙은 21% 올랐는데 판매가는 그대로"가
  의도인지 확인이 필요합니다. 저는 **유지**를 권합니다 — 판매가가 오르면 손절이 쉬워져
  파산 루프가 약해집니다.
- **수리비는 오른다.** `repairCost` 가 `itemLevel` 기반이라 마일스톤만큼 비싸집니다
  (+15 기준 21%). 벌이도 같이 오르는 게 아니므로 `REPAIR_PER_ILVL`(0.035) 을
  0.029 로 낮춰 실질을 유지하는 게 맞아 보입니다 — `__sim__` 으로 확인.
- **해방과 연성액의 곱 순서.** 연성액은 `itemLevel` 에 배수를 곱하므로 해방 보너스에도
  곱해집니다. 즉 해방 → 연성액 순서로 투자하는 게 이득입니다. 의도대로 둡니다.
- **연성액 배수와 곱 순서.** 연성액은 `itemLevel` 에 배수를 곱하므로 마일스톤에도
  곱해집니다. 의도대로입니다 (마일스톤이 배수의 밑을 키움).
